【 权限申请理由申明 (Permission Justification) 】

1. 存储权限 (storage)：
理由：本扩展程序使用 storage API 在本地持久化用户的个性化配置。
具体用途：用于存储全局静默/开启状态、用户选择的主题模式（如 Dynamic, Static 等）以及用户自定义的站点规则列表（如按域名忽略或强制暗色）。这确保了用户在重启浏览器或跨标签页访问时，设置能够无缝延续。

2. 主机权限 (Host Permissions / <all_urls>)：
理由：本扩展程序的核心功能是提供全球站点的“即时”强制暗色渲染，这属于涉及全网域名的 UI/UX 操作。

核心必要性说明（针对审核关注点的答辩）：
- 为什么不使用 activeTab？：`activeTab` 权限需要用户在每个页面上进行显式点击才能生效。对于暗色模式工具而言，这种“滞后性操作”会导致页面加载时出现剧烈的“白色闪烁 (White Flash)”，严重损害用户的视力保护体验。
- 即时注入需求：为了确保暗色背景在 DOM 加载的第一时间生效（document_start），扩展程序必须具备对应站点的预授权。
- 普适性原则：用户访问的站点总量巨大且不可预见，为了提供一致且无感的视觉保护环境，必须请求广谱的主机权限，以确保暗色引擎能在任何被访问的视觉资产上实时应用样式。
